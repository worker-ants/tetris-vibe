### 발견사항

- **[CRITICAL]** 프로젝트 전체에 테스트 파일 및 테스트 프레임워크가 존재하지 않음
  - 위치: 프로젝트 루트 (`package.json`)
  - 상세: `jest`, `vitest`, `@testing-library/react` 등 테스트 라이브러리가 `devDependencies`에 전혀 없으며, `package.json`의 `scripts`에도 `test` 커맨드가 없음. `gameEngine.ts`의 순수 함수들(`initGame`, `startGame`, `togglePause` 등)은 사이드이펙트가 없어 단위 테스트 작성이 매우 용이한 구조임에도 불구하고 단 하나의 테스트도 없음.
  - 제안: `vitest` + `@testing-library/react` 도입. `lib/tetris/` 내 순수 함수부터 단위 테스트를 시작할 것.

---

- **[CRITICAL]** `isStarted` 상태와 `isPaused: true` 초기값의 암묵적 결합으로 인한 회귀 위험
  - 위치: `gameEngine.ts` — `initGame()`, `tick()`, `moveLeft()` 등
  - 상세: `initGame()`은 `isPaused: true, isStarted: false`로 초기화함. `tick()`, `moveLeft()` 등 모든 동작 함수는 `isPaused` 만을 체크하여 게임 시작 전 동작을 막고 있음. 즉 "아직 시작 안 됨"을 `isPaused=true`로 표현하는 암묵적 의존 관계가 존재함. 추후 `isPaused` 초기값을 `false`로 바꾸면 `isStarted` 체크 없이 게임이 즉시 동작해버리는 회귀가 발생할 수 있음. 이를 검증하는 테스트가 없으므로 회귀 감지가 불가능함.
  - 제안:
    ```typescript
    // 각 액션 함수에 isStarted 가드를 명시적으로 추가
    export function tick(state: GameState): GameState {
      if (state.isGameOver || state.isPaused || !state.isStarted) return state;
      // ...
    }
    ```
    그리고 아래 단위 테스트로 커버:
    ```typescript
    it("tick should do nothing before game starts", () => {
      const state = initGame(); // isStarted: false
      expect(tick(state)).toBe(state);
    });
    ```

- **[WARNING]** `startGame()` 및 `togglePause()` 가드 로직의 엣지 케이스 커버리지 누락
  - 위치: `gameEngine.ts` — `startGame()`, `togglePause()`
  - 상세: 다음 시나리오에 대한 테스트가 없음:
    - `startGame(alreadyStartedState)` → 상태 변경 없어야 함
    - `startGame(gameOverState)` → 상태 변경 없어야 함
    - `togglePause(notStartedState)` → 상태 변경 없어야 함 (새로 추가된 `!state.isStarted` 가드)
    - `togglePause(gameOverState)` → 상태 변경 없어야 함
  - 제안:
    ```typescript
    describe("startGame", () => {
      it("returns same state if already started", () => {
        const started = startGame(initGame());
        expect(startGame(started)).toBe(started);
      });
      it("returns same state if game is over", () => {
        const over = { ...initGame(), isGameOver: true };
        expect(startGame(over)).toBe(over);
      });
    });

    describe("togglePause", () => {
      it("does nothing before game starts", () => {
        const state = initGame();
        expect(togglePause(state)).toBe(state);
      });
    });
    ```

- **[WARNING]** Space 키의 이중 역할(시작/하드드롭/재시작)에 대한 통합 테스트 없음
  - 위치: `TetrisGame.tsx` — `handleKeyDown` 콜백
  - 상세: Space 키는 게임 상태에 따라 세 가지 다른 액션을 dispatch함:
    1. `isGameOver=true` → `RESTART`
    2. `isStarted=false` → `START`
    3. 게임 진행 중 → `HARD_DROP`
    이 분기 로직은 `state.isGameOver`와 `state.isStarted`의 조합에 의존하며, 상태 순서가 틀리면 잘못된 액션이 발생함. 현재 이 흐름을 검증하는 테스트가 전혀 없음.
  - 제안: `@testing-library/react`로 렌더링 후 `fireEvent.keyDown(window, { key: " " })`를 각 상태에서 실행하고 `dispatch` mock을 확인하는 테스트 작성.

- **[WARNING]** `gameReducer` switch의 exhaustive 검사 부재
  - 위치: `TetrisGame.tsx` — `gameReducer()`
  - 상세: switch 문에 `default` 케이스가 없음. TypeScript는 `GameAction` 유니온 타입이 완전히 소진되므로 컴파일 에러를 내지 않지만, 런타임에 예상치 못한 액션 타입이 들어올 경우(예: 테스트에서 잘못된 action 전달) 함수가 `undefined`를 반환함. `useReducer`의 initializer와 함께 사용 중이므로 실제 런타임 크래시로 이어질 수 있음.
  - 제안:
    ```typescript
    default:
      return state; // 또는 exhaustive check용 assertion
    ```

- **[WARNING]** 중복된 `[worker-ants]` 주석 태그로 인한 코드 노이즈
  - 위치: `types.ts` 파일 상단
  - 상세: `// [worker-ants] generated by AI Agent` 주석이 3겹으로 중첩되어 있음. 이는 AI 에이전트가 파일을 여러 번 수정하면서 기존 마커를 정리하지 않은 결과로, 코드 가독성을 해침. 테스트 관점에서는 이 파일이 타입 정의만 포함하므로 직접적인 결함은 아니지만, 코드 품질 관리 절차의 부재를 시사함.
  - 제안: 마커 중복을 제거하고, 향후 AI 에이전트 실행 시 기존 마커를 먼저 정리하는 절차 추가.

- **[INFO]** 중력 타이머가 `isStarted`를 독립적으로 체크하지 않음
  - 위치: `TetrisGame.tsx` — gravity `useEffect`
  - 상세: `if (state.isGameOver || state.isPaused) return;` 만으로 타이머를 억제함. `isStarted: false`인 경우 `isPaused: true`이기 때문에 현재는 올바르게 동작하나, `isStarted`를 명시적으로 체크하지 않아 의도가 코드에 드러나지 않음.
  - 제안: `if (state.isGameOver || state.isPaused || !state.isStarted) return;` 으로 의도를 명시화.

### 요약

이번 변경의 핵심 문제는 **코드 자체의 로직보다 테스트 인프라의 완전한 부재**에 있다. `gameEngine.ts`의 `startGame`, `togglePause`, `initGame` 등은 순수 함수로 단위 테스트 작성이 매우 용이한 구조임에도 불구하고, 프로젝트에 테스트 프레임워크조차 설치되어 있지 않다. 특히 `isPaused: true`를 "게임 미시작" 상태로 암묵적으로 재사용하는 패턴과, Space 키의 3중 분기 로직은 회귀 위험이 높은 코드 경로이므로 반드시 테스트로 고정되어야 한다. 기존 기능(`tick`, `moveLeft` 등)도 `isStarted` 가드를 명시적으로 체크하지 않아 초기화 로직이 변경될 경우 조용한 회귀가 발생할 수 있다.
